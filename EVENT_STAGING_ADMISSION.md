# Bounded event-staging admission batch

Two independent opt-in per-camera observation thresholds apply before an active HTTP-triggered event capture is queued:

- SIMPLENVR_MAX_EVENT_STAGING_BYTES: unsigned decimal logical bytes across root *.tmp regular files and every regular file under the camera's temp directory.
- SIMPLENVR_MAX_EVENT_STAGING_DIRS: unsigned decimal count of direct child directories under temp, including empty, active, retained and unrecognized-name directories.

Unset or 0 disables each threshold. If both are disabled, no staging scan is performed. There is no new default. Invalid configured integers fail admission with 503. When observed usage is already at or above an enabled threshold, admission returns 507 before slot reservation, new staging creation, prebuffer pinning, queue submission, metadata append or persistence. Metadata-only event logging bypasses capture policies. The existing minimum-free-space check still runs first.

The Linux scanner opens the camera directory without following a final-component symlink, walks child directories relative to pinned directory descriptors, and uses no-follow metadata inspection. It does not open/read media contents or follow staging symlinks. Special entries, unexpected root temp/.tmp types, metadata/open/read failures and inspection bounds fail closed with 503 rather than presenting partial totals as complete. Root published media and the transient buffer directory are excluded from byte totals. All encountered names, including ignored root names, count toward the 8192-entry bound. Directory names are read in batches of 64, and recursion is limited to four levels below temp. The request context plus a five-second cooperative scan deadline is checked between operations.

Hard-linked files are counted once per path and sparse files by logical size, not allocated blocks. These are deliberately conservative logical totals, not actual unique disk consumption. An unreadable camera directory or staging subtree is not treated as zero usage. A missing temp directory is naturally empty; a missing camera root is an inspection failure. The camera root's parent path remains trusted. Descriptor-relative traversal does not make concurrent file growth, additions, removal, mounts or external filesystem mutation an atomic snapshot. Blocked syscalls remain outside context timing guarantees. Scans hold the existing recording-control mutex but not the registry lock.

These are admission thresholds, not hard quotas or reservations. A newly admitted capture, pinned prebuffer or assembly output may exceed the threshold after the check. Existing continuous/event-buffer writers, queued captures, assembly, recorder starts, exports and direct internal TriggerEvent calls are not newly bounded by these thresholds. A directory containing more than the scan bounds rejects admission even if its configured threshold is much higher; it requires operator inspection or an explicit policy decision. No retained artifacts are deleted, expired, reassembled or renamed. Durable manifests, runtime write/size enforcement, full disk-full handling and a safe operator recovery workflow remain pending.

This batch includes scanner/accounting/bounds tests, no-follow symlink and FIFO tests, cancellation/overflow/configuration tests, and isolated real-handler tests for both threshold boundaries, disabled/below-limit admission, unavailable storage and metadata-only bypass. Tests preserve existing artifacts and release admitted test jobs without running FFmpeg. They do not simulate real disk exhaustion, hostile ancestor replacement, concurrent-growth guarantees or live-camera/container recovery. Full repository vet/race tests and CI must pass before treating the batch as verified. Keep the audit branch unmerged.
