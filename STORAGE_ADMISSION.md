# Opt-in recorder-start storage admission

SIMPLENVR_MIN_FREE_BYTES is an unsigned decimal byte count. Unset or 0 disables this guard; existing deployments do not acquire a new default reserve. For example, 268435456 configures a 256 MiB pre-start reserve. Unit suffixes, negative values, whitespace and overflowing values are rejected when recording admission is attempted.

With a nonzero reserve, a new continuous or event-based recording worker starts only if Linux statfs reports at least that much space available on the existing camera directory's filesystem. The check uses Bavail, not total free blocks, and compares block counts without multiplying into an overflowing byte count. A missing/inaccessible camera directory or failed capacity query fails closed; there is no parent-directory fallback, directory creation or deletion.

Insufficient space maps to HTTP 507; unavailable capacity or invalid policy maps to 503. Rejection occurs before allocating the recording context/wait-group worker or changing start intent. A failed startup resume retains loaded recording intent for a later explicit retry; this patch adds no automatic retry scheduler. Already-running idempotent starts are not rechecked. Explicit stops and transitions to no_recording remain available. Mode changes that would start a worker perform a preflight before stopping the old mode and check again at new-worker admission. If space changes between those checks, the replacement can still be rejected after the old worker stops.

This is a snapshot admission check, not a disk reservation, quota or runtime watchdog. Concurrent writers and admitted cameras can consume the same observed free space. Existing recorders, individual segments, event admission/assembly and exports are not newly bounded by this policy. Staging is never expired or deleted here. Inode exhaustion, write errors, filesystem stalls, durable recovery and a complete disk-full response remain unresolved. statfs runs within the existing recording-control critical section and cannot be canceled if the filesystem blocks. The implementation targets the existing Linux deployment.

Tests cover configuration parsing, overflow-safe comparisons, low-space/unavailable admission without worker allocation, restart-intent preservation, mode-change preflight, stop availability, disabled behavior and HTTP mapping. Real disk exhaustion, reserved blocks for different service users, mount failure and concurrent-writer integration are not simulated by these tests. Keep the audit branch unmerged.
