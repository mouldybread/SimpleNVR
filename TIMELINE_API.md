# Timeline and export policies

Timeline requests use one explicit RFC3339 start_time/end_time pair, positive and at most 26 hours, normalized to UTC. Mixed date/range requests, duplicate/missing boundaries and invalid ranges return 400. Legacy date requests remain HKT-based for old clients; the current browser sends independently constructed local-midnight/next-local-midnight UTC boundaries, including 23-/25-hour DST days.

Recording intervals retain filename-derived UTC starts and probed video durations, with container-duration fallback when necessary. This is metadata-derived timing, not calibrated camera wall-clock time or proof of uninterrupted coverage. Timeline/export selection uses start < window_end and end > window_start, including pre-window overlap. The planner deterministically computes intersections and input-relative In/Out offsets. Missing coverage, duplicate/overlapping intervals or ambiguity return 409 before pinning or video headers. Comparisons have no rounding tolerance. Empty selections return 404; invalid plans return 400; more than 128 inputs return 413.

## Trim execution

Whole-clip-aligned plans retain the existing pinned-descriptor stream-copy path, with whole-clips-untrimmed policy and Trim-Applied=false. Plans requiring boundary trims use a new, deliberately restricted decoded-video path. Unsupported cases fail explicitly; there is no silent fallback to whole clips.

Supported trimmed inputs contain exactly one stream: unrotated 8-bit yuv420p video, even and matching dimensions across clips, dimensions at most 4096 each and pixel count at most 3840x2160. Reported average and nominal frame rates must match and lie between 10 and 60 fps. Every selected part must span at least two nominal frame periods. These metadata checks do not certify perfectly constant actual frame cadence. Audio-containing, subtitle/data, rotated, high-bit-depth or incompatible inputs return 422 rather than silently lose or transform streams. Audio-aware trimming is a follow-up; audio in whole-clip copy exports is not newly restricted by this profile.

Each source track is decoded from its beginning and its PTS normalized to its first decoded frame. trim retains frames with normalized timestamps in the half-open [In,Out) interval. Retained parts are reset to zero and concatenated. H.264 libx264 CRF 0 encodes the retained yuv420p samples losslessly; this is not bitstream/container/metadata preservation. The runtime image build checks for libx264. Output uses VFR timestamps rather than an imposed output frame rate.

Accuracy is frame-granular, not wall-clock-exact. Non-frame-aligned boundaries are quantized by the retained source frames; separately resetting parts can shift their phase by a frame fraction. Filename timestamps and camera clock uncertainty remain. A 1.55-second request can yield 1.50 seconds of retained 10-fps frames. Successful output duration must differ from the planned duration by no more than two maximum nominal input frame periods. This check is not proof of every frame's timing or completeness.

Trim requests are limited to ten minutes, a two-minute render budget including profile inspection, and 256 MiB output. Profile probes share the global two-probe semaphore, use five-second budgets and bounded output. Rendering uses two codec threads and one complex-filter thread. Existing two-export admission and 128-input bounds remain. Filesystem stalls remain outside context guarantees.

Rendering completes into an owner-only, immediately unlinked temporary file before download headers. A capped writer rejects overflow; failed/canceled/oversized renders close the file and return an error, never the partial media. Completed media is duration-probed and input descriptors revalidated, then served from its open descriptor. Unsupported profiles return 422, resource limits 413, deadlines 504, metadata failures/changes 503, and other render/validation failures 500. Once download starts, client disconnect can still leave the client with incomplete bytes; pins/output close when the joined handler returns.

Headers identify decoded-video-frame-window, Trim-Applied=true, Accuracy=frame-granular-not-wall-clock-exact and Audio-Policy=video-only-inputs. Requested boundaries remain explicit. Source-Start/End describe whole-source metadata bounds; Media-Start/End are omitted for trims rather than inventing exact first/last-frame wall-clock times. Output-Duration-Seconds reports probed length. Trim-Required describes the plan; Trim-Applied describes execution. The UI does not yet display these policies/errors.

## Pinning and metadata limits

Selected identities are verified with O_NOFOLLOW/O_NONBLOCK and retained through FFmpeg Run. Generated descriptor references replace original paths; manifests are unlinked and inherited. Pinning survives unlink/path replacement after verification, not in-place writes or hostile parent-directory replacement. Two admitted exports may retain source disk blocks and, for trims, up to 256 MiB anonymous output each until download completes. No general media sandbox is claimed.

Metadata selection retains its 30-second budget, 8192-entry scan limit and 2048-result identity/size/mtime-aware LRU. At most two probes run; each has a five-second budget and two-second pipe cleanup allowance. Unreadable eligible old files can block a selection; errors do not become fictional coverage or partial arrays. Timeline/export/proxy work participates in cancellation and shutdown joining.

## Verification and remaining work

Tests retain window/DST, planner, metadata/cache, pinning and cleanup coverage. New tests compare decoded frame hashes against source-window hashes for long-GOP/B-frame clips, single-clip fractional boundaries and multi-clip trims; check profile restrictions, output limits, cancellation and handler headers; and retain whole-clip copy tests. The local prototype verified matching 49-frame and 15-frame sequences, but that is not repository CI or runtime-image verification. Full authenticated slow-client integration, audio-aware trimming, broader codec/profile support, UI reporting, canvas DST geometry, automatic segment advancement, storage recovery policy and final re-audit remain pending. Keep the audit branch unmerged.
