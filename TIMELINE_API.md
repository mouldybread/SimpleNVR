# Timeline windows and recording intervals

GET /api/timeline/recordings accepts one RFC3339 start_time/end_time pair with explicit offsets or Z, a positive elapsed window of at most 26 hours, and no date parameter. Boundaries are normalized to UTC. Duplicate/missing boundaries, mixed date/range requests and invalid ranges return 400. The legacy date=YYYY-MM-DD path remains HKT-based for old clients; no parameters mean the current HKT day. The browser uses independent local-midnight/next-local-midnight boundaries converted to UTC, including 23-/25-hour DST days, without falling back to legacy date requests.

Responses remain JSON arrays. X-Timeline-Window-Start/End expose normalized boundaries; X-Timeline-Window-Mode is absolute or legacy-hkt. X-Timeline-Duration-Policy is now probed-media. StartTime retains the original UTC filename timestamp; EndTime adds the probed video-stream duration, falling back to container duration only when the video stream lacks a usable duration. This is metadata-derived media length, not verified uninterrupted coverage or a calibrated camera clock.

Timeline and export input selection share the strict overlap rule: recording_start < window_end and recording_end > window_start. Clips beginning before the requested day are included if they overlap; clips ending exactly at the start or beginning exactly at the end are excluded. Returned starts are not clipped, preserving playback offsets. Export selects whole overlapping clips; trimming, gaps and duplicate/overlap policy are not implemented.

## Resource and failure policy

The Linux runtime probes an already-open, regular, nonempty MP4 descriptor with ffprobe using MOV demuxing and file/pipe protocols. Each probe has a five-second context budget including semaphore waiting, with a two-second WaitDelay for process/pipe cleanup. At most two metadata probes execute concurrently. Metadata selection has a 30-second request budget and scans at most 8192 directory entries across its camera snapshot. Filesystem stalls remain outside context timing guarantees.

The shared in-memory LRU caches at most 2048 successful durations. Hits require matching file identity, size and modification time. Changes during probing or pathname replacement prevent caching. Failed probes are not cached. This is not cryptographic content validation: hostile same-inode rewrites restoring size/mtime, parent-directory replacement and changes after selection are not fully prevented. Export still reopens selected paths later; pinning export inputs is follow-up work.

Files beginning at/after the window end need no probe. Earlier files must be inspected because their overlap cannot otherwise be established. Cold or large archives can exceed the scan/time budget. Unreadable eligible media, changed files and scan limits fail the entire selection with 503; metadata deadlines return 504. X-Recording-Metadata-Status is unavailable. No partial array/export or invented ten-minute fallback is returned. Request cancellation stops probes; timeline jobs join export/proxy jobs in shutdown tracking. A corrupt old file can therefore block selection until inspected or repaired; this is deliberate fail-closed behavior, not a recovery feature.

Tests cover injected duration decoding, cache invalidation/eviction, concurrency/cancellation/deadlines, exact overlap boundaries, explicit windows, synthetic short partial/event MP4s and corrupt media. Filename/unit fixtures do not prove live-camera timing. Full authenticated browser playback/export integration, the canvas's fixed 24-hour/DST geometry, automatic segment advancement, export trimming/gaps, storage recovery policy and final re-audit remain pending.
